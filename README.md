# Lucas Eckert

**Backend Software Developer · Java / Spring Boot · Distributed & Data-Intensive Systems**

I build and evolve backend software, from understanding a problem to designing, implementing, testing, and delivering a solution. I'm particularly interested in what makes systems difficult to change: unclear ownership, distributed state, integration boundaries, and the gap between expected and observed behavior.

Java, Spring Boot, and PostgreSQL are my foundation. Distributed systems, event-driven architectures, and data-intensive applications are areas where I deepen that practice. I prefer choosing an approach for the problem it solves, not for the technologies it introduces.

## Professional experience

At **WEG**, I develop backend software for industrial applications. My work includes domain modeling, shared backend capabilities, authentication and authorization, data integration, and observability. Much of the challenge is evolving existing systems without losing the behavior and contracts other applications depend on.

That experience has shaped how I think about engineering: understand the constraints before changing an architecture, make responsibilities explicit, and verify changes through tests and operational signals.

## Projects that shape my approach

**[VellumHub](https://github.com/Luca5Eckert/VellumHub)** is an event-driven recommendation platform. It explores how services can collaborate through events while keeping reads independent of upstream availability. Building it has meant working through the real costs of distributed boundaries: consistency, retries, idempotency, and the ability to understand failures.

**[Kairos](https://github.com/Luca5Eckert/Kairos)** is a hybrid retrieval engine combining vector search and graph-based ranking. It explores when the added complexity of a graph is justified by retrieval quality—and how to evaluate that gain alongside latency rather than presenting either number in isolation.

I've also worked on **[Portal Conecta](https://github.com/Portal-Conecta/core-backend)**, a collaborative academic platform where I contributed to backend architecture, an API gateway, and observability, and **[Trama](https://github.com/Luca5Eckert/trama)**, a Go/PostgreSQL project exploring modular design and domain boundaries.

## Engineering perspective

I value software that can be understood, tested, and evolved. For me, architecture is not a diagram or a list of patterns: it is a set of choices about what belongs together, what can fail independently, and what evidence would justify changing the design.

The [portfolio](https://lucas-eckert.vercel.app) contains the deeper case studies, technical articles, diagrams, and measured trade-offs behind this work.
